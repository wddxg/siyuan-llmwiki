# Wiki 概念说明

## 什么是 LLM Wiki

LLM Wiki 是一种知识管理范式，核心思想是：

> 原始素材是源代码，LLM 是编译器，Wiki 是可执行产物。

这不同于传统 RAG 的"每次查询从零检索"。Wiki 模式将知识**编译一次、持续维护**。

## 知识库结构

```
<知识库>/
├── 结构约定          ← 元信息、导航入口
├── 总索引            ← 主目录
├── 操作日志          ← 只追加的操作记录
├── 收件箱            ← 待处理资料入口
├── 原始资料/         ← 不可变
│   ├── 文章/
│   ├── 论文/
│   ├── 仓库/
│   ├── 笔记/
│   └── 数据/
├── 实体              ← 人物、组织、产品
├── 概念/             ← 主题、技术、方法论
│   ├── 参考/
│   └── 论题/
├── 对比              ← 并排分析
└── 问答归档          ← 沉淀的结论
```

## 三种操作模式

### Ingest（摄入）

将外部素材导入知识库：

1. 判断素材类型
2. 写入原始资料区（不可变）
3. 分析关键实体和概念
4. 生成或更新 wiki 页面
5. 建立交叉引用
6. 更新索引

一份素材可能触发 5-10 个页面的更新——这就是知识的**复合增长**。

### Query（查询）

从 wiki 中检索和综合信息：

1. 读索引定位相关页面
2. 读取相关页面内容
3. 跨页面综合分析
4. 生成带来源引用的回答

**硬规则**：Query 只读 wiki 页面，不读原始文件。

### Lint（自检）

检查知识库的健康状态：

- 缺失的结构页面
- 孤立页面（没有被其他页面引用）
- 缺失的交叉引用
- 长期未编译的原始素材
- 内容矛盾和过时风险

## 交叉引用

wiki 页面之间通过 `[[页面标题]]` 语法互相链接，形成知识网络。

```
Transformer 架构 → 引用 → [[上下文窗口]]
上下文窗口 → 引用 → [[RAG]]
RAG → 引用 → [[向量数据库]]
向量数据库 → 引用 → [[Embedding]]
```

这种双向链接网络是 Wiki 区别于线性文档的关键特征。

## 置信度标记

每个 wiki 页面都有置信度标记：

- **high**：基于高质量来源（论文、官方文档）
- **medium**：基于一般来源（博客、社区讨论）
- **low**：来源不足或存在争议

## Canonical vs Derived 页面

- **Canonical 页面**：长期维护的真实页面（实体、概念、对比）
- **Derived 页面**：派生视图和聚合页（索引、日志）

原则：Derived 页面服务于 Canonical 页面，不得反客为主。

## 原子编辑原则

1. 能改一段就不要重写整页
2. 能改一页就不要刷新整棵子树
3. 能直接维护 Markdown 就不要包一层"说明页"
